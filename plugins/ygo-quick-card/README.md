# 游戏王查卡快车道（ygo-quick-card）

「这张卡什么效果」的答案本来就写在卡面上 —— 本插件把它从模型链路里摘出来，**直接查、直接发**。

| | 现在 | 之前（走模型 + `ygo-ruling` 技能） |
|---|---|---|
| 耗时 | 约 1 秒（打卡库接口 80~450ms） | 几十秒（主模型在 NVIDIA 免费端点，一次带工具往返就要几十秒，查一张卡要 2~3 轮） |
| token | **0** | 每轮几百到上千 |
| 内容 | 卡面原文（查得到就是查得到） | 模型复述（可能记错、可能念出内部编号） |

## 怎么用

**说卡名就行，@ 不 @ 都认：**

```
羽毛扫                  → 「羽毛扫」→【鹰身女妖的羽毛扫】[魔法] ①：对方场上的魔法·陷阱卡全部破坏。
灰流丽什么效果           → 【灰流丽】…
黑魔导                  → 「黑魔导」→【黑魔术师】…（命中简中别名，会点明对应关系）
@她 羽毛扫              → 当然也认
查卡 灰流丽             → 触发词只是"更明确地要查"的意思，不是必需
```

不打 @ 也不用打命令 —— 群里的消息**先被拿去问一次卡库**，对不上就**原样放行给模型**，所以只会变快，不会乱答。想收窄成「必须 @ 才查」，把设置里的**「群里什么时候查卡」改成 `at`**。

名字对得上不只一张时，**发最可能那张的图 + 问一句**，不猜：

```
「羽毛扫」对得上 2 张，你说的是这张吗？不是的话请给我完整的卡名：
1. 鹰身女妖的羽毛扫 ｜ [魔法]
2. 狮鹫的羽毛扫 ｜ [魔法]
（同时发出第 1 张的插图）
```

答确定的卡时，会把**卡片插图一起发出来**（设置里的「抢答时一起发卡片插图」可关）。图走 `sender.sendImage` 同一条管道（串行/限频/去重/留档）；**发图失败不会退回模型** —— 卡面文字已经发出去了，这时候再放行只会叠成两条。

## 划清界限：只说卡面，不碰判例

问「能不能发动 / 会不会被无效 / 连锁怎么处理」这类**要推理**的问题时，插件**不拦**，照旧交给模型（`skills/ygo-ruling` 会去取 Lua 脚本）。那是生成式判断，插件给不出来。

判据是关键词（见 `logic.js` 的 `RULING_RE`），命中即放行 —— 宁可慢，不乱答。

## 抢答的判定（为什么不建卡名索引）

「这句话里哪几个字是卡名」是不可解的字符串问题：几万张卡 × 8 种别名，还夹中文虚词。本地子串匹配的话「龙」会命中几百张、还和「恐龙」「龙虾」打架。

换个方向就有解 —— **「整句话像不像一个卡名」是可以验的**：

1. 把消息去噪（拆掉 @ / 寒暄 / 疑问语气 / 标点）成候选查询串；
2. 把它**整串**丢给卡库（ygocdb）；
3. 用返回的匹配质量反推"用户问清楚了没有"：
   - 有别名与之**精确相等** → 直答；
   - 结果可疑地少时用**去虚词的核心词**补搜一次（`真红眼的黑龙` → `真红眼黑龙`），补搜结果确实更准才采用；
   - 候选收敛到少数几张 → 按设置自己挑一张（回复里点明按哪张理解）或列清单；
   - **明确在对她说**（私聊 / @ 她 / 带触发词）且还是查不到时，再用**去掉尾字**的词补搜一次：只剩一张就直接给卡面，多张才问「你要的是哪一张」（见下）；
   - 对不上 / 候选一大片 → **一律放行给模型**。

「对不对」是卡库说的，不是我们猜的 —— 所以免命令也几乎不会答错。副作用只是每条"像查卡"的消息多一次 HTTP（0 token）。

### 两种"不确定但要问一句"的情况

| 情况 | 例子 | 为什么值得问 |
|---|---|---|
| **截断补搜**（去掉尾字再搜） | 「阁楼妖」→ 按「阁楼」搜到【阁楼上的妖怪】+【莫忘阁楼怪】，问「你要的是哪一张」 | 卡库对「阁楼妖」**只回 1 条**（阁楼上的妖怪）—— 那张卡的任何别名里都没有「妖」字，所以这不是别名匹配失败，是**这个词本身查不到它**。而「阁楼」两条都给。模型当时也要花 1 分 44 秒才问出同一句话 |
| **跳字缩写**（卡库已收敛到 1~2 张） | 「阁楼妖」对【阁楼上的妖怪】= 0 分（跳掉了「上的」和「怪」） | 连续子串规则对跳字无能为力，但候选已经收敛了，问一句比让模型花几十秒做同一件事划算 |

这两条都**只提问、不笃定**（措辞比普通候选清单更退一步），且都只对**含中文、首字相同、且覆盖率/长度比在合理区间**的查询生效（见 `weakMatch` 的四道约束）。截断补搜只在"明确在对她说"时启用 —— **群里路过的闲聊不会被她追问一张卡**。设置里「卡名跳字缩写时问一句」可以整个关掉。

**但只剩一张候选时不再问，直接给卡面（含效果）。** 问"你要的是哪一张"在一个候选时毫无意义，还会把用户要的效果藏起来 —— 这是实测踩到的两次坑：

| 用户打的字 | 卡库回什么 | 旧行为 | 现在 |
|---|---|---|---|
| 查卡 莫忘阁楼妖 | 原词回 1 条【莫忘阁楼怪】（末字怪→妖，0 分）；「莫忘阁楼」也回这 1 条 | 回「没查到同名的卡…你要的是哪一张？」+ 只列卡名，**没有效果** | 378ms 直接回完整卡面（含效果）+ 插图 |
| 查卡 冥铭途阁楼妖 | 原词 0 条；「冥铭途阁楼」回 1 条【莫忘阁楼怪】（卡库自己做**多片段模糊匹配**） | 我们的采纳门槛是"卡名包含搜索词"，这张别名里没有这个连续串 → 0 分被筛掉 → **整条放行给模型** | 287ms 直接回卡面 + 插图 |

末尾会注明**按哪个词找到的**（`（卡库里没有正好叫「X」的卡，这张是按「Y」找的；不是它的话给我完整的卡名）`），不做无根据的断言。

放开的门槛有四道闸（`looseMatch`），缺一不可：① 卡库对这个词**恰好**回 1 条；② 搜索词**每个字**都在这张卡的名字里；③ 搜索词与卡名至少有 **≥2 字的连续公共段**；④ 搜索词 **≥3 字**。实测这四道闸挡住了「明天有空吗」「灰流丽真的烦」「这把输了」这类闲聊（卡库对它们本来也会回一张卡）。设置里「补搜只剩一张时直接给卡面」可关。

## 触发条件（什么时候会抢答）

由设置里的 **「群里什么时候查卡」** 决定，两档：

| 值 | 群里没 @ 她时 | 说明 |
|---|---|---|
| `any`（默认） | 任何像卡名的消息都试一次查库 | 免 @ 免命令；对不上就放行给模型 |
| `at` | 必须 @ 她 / 私聊 / 带触发词 | 更保守；触发词默认 `查卡 / 查牌 / 卡查 / 什么效果 / 是什么卡` 等，可在设置里改 |

**私聊**恒认，与这一项无关。

⚠️ `any` 档下抢答**先于响应档位发生**：即使响应档位是 1 档「仅艾特」，群里非 @ 的查卡也会被答（模型不跑）。这是刻意的 —— 免 @ 快车道就是要在模型被叫醒之前把卡答掉；不想要就改回 `at`。

不管哪一档，**判例问题一律不抢答**（`能不能发动 / 会不会被无效 / 连锁…`，见 `RULING_RE`），交给模型。

## 实现要点（改这个插件前先看）

- **必须包 `Orchestrator.prototype.onIncoming`**：那 5 个 hook（`before-context` / `before-llm-messages` / …）都只在**已经排定一次模型会话之后**才触发，挂上去就省不掉模型钱了。
- **顺序和复读机（`repeat-echo`）相反**：复读机是先调原方法再跟一句（旁路增强）；本插件必须**先判定、命中就自己发完、不调原方法** —— 否则模型回复 + 插件回复 = 两条。同步榨查询串（纯字符串、零延迟）→ 榨不出立刻放行；榨得出才异步查库，查证期间先不排唤醒。
- **卡名归一化 / 打分 / 去虚词补搜条件必须与 `skills/ygo-ruling` 保持一致**（两处判断一旦分叉，会出现"技能说是这张、插件说是那张"的分裂）。改一处记得同步另一处。
  ⚠️ 例外：`truncatedForms`（截断补搜）与 `weakMatch`（跳字缩写）**不需要同步到技能**，因为它们**只产出提问、绝不产出确定回答**，不存在"两处断言不一致"的可能。技能那边由模型自己问，本来就会问。
  ⚠️ `looseMatch`（卡库只回一张就认）**也不需要同步**，但它是"卡库说唯一，我们说就是它" —— 判定权在卡库，不在我们的打分规则上，所以不存在与技能分叉的问题。
- **检索和打分要分开看**：用户报"明明有这张卡却没查到"时，先拿他的原文直接打一次 `https://ygocdb.com/api/v0/?search=<词>`，看返回里有没有那张卡。没有 → 是检索词的缺口（换词 / `truncatedForms`）；有但分低 → 才是打分阈值的问题。改阈值修不好"库里就没返回"。
- **同分排序：整词命中 > 主名命中 > 卡库顺序**。判据是"查询词是不是候选名里独立的一段"（卡名惯用空格分词）：查「霍普」时「No.39 希望皇 霍普」✅，而「剑斗兽 重斗」（简中名「剑斗兽 霍普洛姆斯」）只是半个词 ❌ —— 两者同为 60 分，没有这条就会被卡库顺序带走、发错图。`scoreCard` 只多回报 `exactWord` / `onPrimary`，**不改 score 语义**。
- 卡片插图：`https://cdn.233.momobako.com/ygopro/pics/<密码>.jpg`。地址**只用于发图**，绝不写进文本 —— 文件名就是卡片密码。
- 发送走 `sender.sendTextBatch` 完整管道（串行 / 限频 / 去重 / **留档 appendSelf**）。留档不能省：模型后续每轮都读"已读信息"，看不到自己发过的卡面，用户接着问「那能不能发动」就成了没头没尾的一句话。
- 顺手 `store.markEntryRead` 标已读，免得下一次 wake 把这条当"未读信息"再喂给模型。
- 卡面里**不含密码 / cid**（内部编号，模型那条链路上也早就剥掉了）。

## 排障

- `data/ygo-quick-card.json` 是状态文件（30 秒节流写一次，**只在成功抢答时强制落盘**）：`answered` 一直在涨 = 钩子在干活；`asked` = "没对上但问了用户一句"的次数；`cacheSize` 是查询缓存条数。⚠️ 别把它的计数当实时状态 —— 它是个快照，放行/放行/再放行都不会更新它。
- 控制台「插件」页能看到启用状态；能力 `ygo-quick-card.status` 可查统计。
- **放行原因现在会写进主日志**（`data/logs/qq-agent-*.log`，tag `ygo-quick-card`）：`「X」对不上卡库，放行给模型` / `冷却中，放行给模型：X` / `原词「X」查不到同名卡，已按「Y」再搜一次` / `原词「X」查不到同名卡；卡库对「Y」只回【Z】这一张，按它答`。以前这些只走 `api.log`（仅控制台、不落盘），所以"为什么走了模型"在日志里查不到，只能离线复现 —— 已经修掉。
- 完全不抢答：先看开关是否关掉，再看是不是**模型正在这个群回话**（`onlyWhenIdle` 会让路），以及同群冷却（默认 1500ms）。
- 「明明有这张卡却放行给模型」：多半是判例词命中（如卡名里带「发动」），或查询串没对上卡库。排查时**先直接问一次卡库**，别怀疑打分：
  ```bash
  node -e "fetch('https://ygocdb.com/api/v0/?search='+encodeURIComponent('阁楼妖')).then(r=>r.json()).then(j=>(j.result||[]).forEach(c=>console.log(c.id,c.cn_name,'|',c.sc_name,'|',c.md_name,'|',c.nwbbs_n,'|',c.cnocg_n)))"
  ```
  实测教训：用户打「阁楼妖」，卡库**只回 1 条**（阁楼上的妖怪），而他真正要的【莫忘阁楼怪】压根不在返回里 —— 这种"库里就没有"的缺口，靠改打分是修不出来的，只能换检索词（截断补搜就是这么来的）。
- 关掉开关 = 摘钩子，零副作用。

## 离线自测

`logic.js` 不 import 项目任何东西、fetch 由外部注入，所以能脱离 Electron 直接跑：

```bash
node -e "import('./plugins/ygo-quick-card/logic.js').then(async L=>{
  const e=new L.QuickCard({settings:()=>({}),fetchImpl:(u,i)=>fetch(u,i),log:console.log,warn:console.log});
  console.log((await e.compose('group:1','@她 羽毛扫',{lenient:true})).text);
})"
```

判定规则的回归网在 **`test/ygo-quick-card-logic.mjs`**（已挂进 `npm test`）—— 42 项，用**注入的假 fetch + 卡库真实返回形状**跑，不联网。改动 `extractQuery` / `scoreCard` / `weakMatch` / `truncatedForms` / `looseMatch` / `decide` 后**必须**跑它：这个插件是 0 token 直发、没有模型兜底，规则回归的表现是"静默地把某张卡答错"，在群里很难被发现。
