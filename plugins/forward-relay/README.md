# 屎壳郎（forward-relay）· 使用教程

> **一句话**：把 A 群里的「聊天记录」卡片（合并转发）搬到 B 群，但**同样的一条绝不搬第二次**。

---

## 1. 它是干什么的

QQ 群里那种点开才能看的「聊天记录」卡片，就是**合并转发**。想把其中的一条让另一个群也看到，
手动要走「点开 → 选中 → 选群 → 发送」，重复劳动；更烦的是同一条被不同的人转来转去，最后几个群刷屏。

屎壳郎替你干这件事：

```
来源群（盯着看）                目标群（可以搬过去）
  ┌──────────┐                  ┌──────────┐
  │ 有人发了  │   存档 + 比对     │ 已经有   │ → 完全不管（不问、不搬、不打扰）
  │ 合并转发  │ ───────────────▶ │ 同一条？ │
  └──────────┘                  │ 没有     │ → 才问你（或让机器人自己判断）
                                └──────────┘
```

三条硬规矩：

1. **只搬你没见过的**。判断靠的是内容指纹（去掉空行、去掉「共 N 条」这种开头之后算的一串码），
   同一个卡片转两次、换行不一样，也算同一条。
2. **不主动刷屏**。默认模式下插件只私聊问你，你回一句才真的发出去。
3. **判断全在本地**。「有没有同一条」是插件读文件算出来的，不调模型、不联网。

---

## 2. 装好后三步就能用

1. 打开机器人的设置页 → **插件** → 找到 **屎壳郎**。
2. 填两个框（**必填**）：
   - **来源群**：要盯着看的群，群号用逗号隔开。例：`123456,234567`
   - **目标群**：可以搬过去的群，同样逗号隔开。例：`345678`
3. 其余保持默认（ask 模式）。等群里有人发合并转发，插件会**私聊你**两条：先一条**原始卡片**（点开就是原文），再一条带编号的询问：

   ```
   📮 屎壳郎 · 1 条待你拍板
   👉 要发就回：\转发 1
   ⏳ 5 分钟没回复就自动丢掉（不再提醒）

   【1】来源 某某群（123456） · 📎 上面第 1 张卡片
        张三 · 12 条 · 收到 10-05 14:20
        → 另一个群（345678）
    ...预览...
   ```

   你回 **`\转发 1`**，它才真的发到目标群。**5 分钟**没回复，它就当你没看见，
   静默丢掉（只写日志，不再来催你；存档 `.md` 原件还在）。
   编号**每天从 1 重新开始**，同一份内容在「暂存去重窗口」（默认 12 小时）内**只问你一次**。

   **目标群里已经有的，不会摆出来**：某个目标群的存档里已经有同一条内容时，
   询问里的 `→` 只列还缺这条的群，底下补一句说明（`（A群 里已经有这条了，没列进备选）`）。
   要是你偏要点着名往那个群发 ——

   ```
   \转发 1 345678
   ⚠️ #1 要发的「另一个群（345678）」里已经有这条内容了（同一份，指纹 3f9a21c7），薄荷没有发。
   还要再发一遍的话，就再回一次同样的口令：\转发 1 345678 —— 这次薄荷就真发过去。
   （10 分钟内有效；不想发就 \不转 1）
   ```

   再回一次同样的口令，它就真发（防止手滑把重复内容又灌一遍群）。

> 填完不用重启，保存即生效。

## 3. 两种模式：你拍板 / 它自己拿主意

| | **ask（默认）** | **auto** |
|---|---|---|
| 谁决定要不要搬 | 你，回 `\转发 1` | 机器人自己判断 |
| 花不花钱 | **0 token**（纯本地判定） | 多一段提示词，会吃一点上下文 |
| 怎么收到消息 | 私聊一条固定文案，等你的口令 | 私聊告诉你「已转到 X 群」 |
| 适合谁 | 想全权掌握、怕机器人乱发 | 群多、想让它自己筛 |

**auto 模式怎么驯服它**：填设置里的「auto 判定口径」，用大白话写你要什么，例如：

```
只转「沙雕 / 抽象 / 搞怪」的内容——越离谱、越好笑越该转。
正经通知、广告、求赞、求助、吵架、私人闲聊 → 不转。
```

机器人每条都要给自己打一个 1-10 的**自信度**，低于「自信度放行线」（默认 7）的一律不发、
也不会来问你。口径写得越清楚，它越不容易自作主张。

## 4. 口令表

口令都在**消息开头**打，只有主人能用（别人打同样的字会被当普通聊天）。

| 口令 | 作用 |
|---|---|
| `\转发 <编号>` | 把第 N 条搬到它列出的**全部**目标群（已经有这条的目标群不在里面） |
| `\转发 <编号> <群号>` | 只搬到指定的那一个群；要是那个群**已经有**这条内容，会先问你一句，同样的口令再回一次才真发（10 分钟内有效） |
| `\转发` | 不写编号 = 最新那一条 |
| `\不转 <编号>` | 丢掉这条（存档还留着，之后也不会再来问你同一份内容） |
| `\转发状态`（`\转发清单`） | 看待处理的、指纹、存档统计 |
| `\转发测试` | 往你私聊发一条**假的**合并转发，验证机器人支不支持这个格式 |
| `\转发帮助` | 直接在聊天里看这份说明 |

> 第一次用建议先发一次 `\转发测试`：能收到两条假卡片，就说明你的机器人版本支持转发，之后才能正常搬。

---

## 5. 它把文件放在哪

都在机器人的**数据目录**里，全是明文，随时能看能删：

| 内容 | 位置 |
|---|---|
| 展开后的聊天记录 | `文档文件夹/转发存档/<群号>/<日期>_<指纹8位>.md` |
| 状态（指纹索引、待确认清单） | `data/forward-relay/state.json` |
| 运行日志 | `data/logs/forward-relay.log` |

存档默认 **24 小时**过期（`存档有效期`），每个群最多留 300 份，到点自动清理。
那些 `.md` 是普通文档，机器人自己的「文档阅读」能用，装了「文件修改」插件也能改。

## 6. 设置项速查（只讲容易看晕的几个）

| 设置 | 什么意思 |
|---|---|
| **来源群 / 目标群** | 上面说的「盯着看」和「可以搬过去」，两边是全交叉判断的 |
| **存档有效期（小时）** | 「有没有同一条」只在这个时间窗口里比。默认 24；调大 = 隔天也算重复 |
| **扫描间隔（秒）** | 每几秒看一眼来源群有没有新卡片，默认 20 |
| **处理范围** | `new-only`（默认）= 只认装上**之后**的新转发，避免第一次跑把几百条历史全翻出来；`all` = 连历史一起处理，第一次慎用 |
| **原文先发一份** | 默认开：发现有新卡片时，先把**原始聊天记录卡片**直接私聊发给你（点开就是原文），再发带编号的询问。关掉就只发文字预览 |
| **一轮最多先发几张原文** | 默认 5，防止某个群一口气刷十几条把私聊刷爆；超出的下一轮接着发 |
| **未回复超时（分钟）** | 默认 5：ask 模式下你没回口令，过了这么久就**静默丢掉**（只写日志，不再催你；存档原件留着）。0 = 一直等你拍板 |
| **暂存去重窗口（小时）** | 默认 12：同一份内容（按内容指纹认，不看 message_id）在这个窗口内只问你一次。你回过 `\不转`、超时丢过、已经转出去的，窗口内都不会再拿来烦你。0 = 关掉去重 |
| **暂存编号每天重置** | 编号按本地日期，每天从 1 重新开始（跨天自动归零，会跳过还挂着的编号免得撞号） |
| **兜底拉取** | 开着（默认）：来源群如果不在机器人「允许的群」列表里（这种情况它根本不记录那个群），插件就自己向机器人拉最近几条来判断，**只读、不发言、不改设置** |
| **安静群** | 这几个目标群判定为重复时不再写日志，只影响日志，不影响判定 |
| **合并转发失败时回退纯文本** | 转发格式不被支持时，宁可把正文当普通消息发出去，也不要整条丢掉 |

## 7. 常见问题

**Q：来源群填了，可它一直没反应？**
多半是那个群不在机器人的「允许的群」列表里 —— 不在列表里，机器人不记录该群聊天，插件自然也读不到。
保持「兜底拉取」开着（默认开）就会好转；要是还不行，看日志 `data/logs/forward-relay.log`，里面会写明原因。

**Q：会不会一装上就把历史几百条转发全刷出来？**
不会。默认只处理**装上之后**的新消息。

**Q：会不会重复搬、刷屏？**
不会。按内容指纹比，目标群里已经有同一条就彻底安静（不问你、不搬、连日志都懒得写）。
同一个群同一个人 1 秒内也不会连发两次。

**Q：要花钱吗？**
ask 模式 0 token —— 判定、存档、比对全是本地文件操作。
auto 模式每轮会多一小段提示词给机器人看（这就是它判断的依据），花的是这点上下文钱。

**Q：清单里写的 `web_fetch` 权限是干嘛的？**
用来调**本机**机器人的接口（默认 `http://127.0.0.1:3000`）发消息、拉群名、取转发内容。
它不访问外网、不上传任何东西。

**Q：怎么关掉 / 卸载？**
设置页把「总开关」关掉即可；想彻底去掉就删掉 `plugins/forward-relay/` 整个目录。
存档和状态在数据目录里，要清理就自己删。

## 8. 依赖（都不是必须的）

| 依赖 | 作用 | 没有会怎样 |
|---|---|---|
| `owner-identity` 或 `group-reports` | 用来知道「主人是谁」（发给谁） | 在插件设置「询问发给谁」里手填一个 QQ 号就行 |
| `auto-receipt`（回执单） | 每轮干了什么写进回执单 | 什么都不影响，只是少一份流水 |

宿主需要支持：主人口令（commandRoute）、工具闸门（tool.guard）、每轮钩子与后台定时器。

---

## 9. 隐私说明

- 判定与存档**全部在本机完成**，插件不联网、不上传、不写任何外部服务。
- 插件**不读**你的聊天记录之外的任何文件，只读它在盯着的那几个群的存档。
- 「原文先发一份」、询问、告警、测试消息**全部只发主人私聊**，绝不发到任何群里。
- 真正会落到群里的，只有你（或 auto 模式下的机器人）确认要搬的那条转发。

## 10. 更新记录

### 1.1.0（2026-10-04）

**新增**

- **没回复就丢掉**（设置项「未回复超时」，默认 `5` 分钟，填 `0` = 一直等你）：ask 模式下发出询问后，5 分钟没等到你的口令，这条暂存就**静默丢掉** —— 只写插件日志，不再私聊催你；硬盘上的存档 `.md` 照旧留着。
  - 计时从「原文卡片真的送到你手里」那一刻开始算（一轮里卡片是分批推的），不会让你刚看到就来不及回。
  - 询问里会多一行 `⏳ 5 分钟没回复就自动丢掉（不再提醒）`；`\转发状态` 里的「还剩多久」也改成显示这个回复时限。
- **暂存去重窗口**（设置项「暂存去重窗口」，默认 `12` 小时，填 `0` = 关掉）：同一份内容在窗口内**只问你一次**。
  - 按**内容指纹**认，不看 `message_id` —— 来源群不在白名单里时插件会走「兜底拉取」，而拉取给的 `message_id` 每轮都会变，于是同一份转发会被反复当成新转发再来问你（真机上同一份 37 条的转发被问了三遍）。
  - 还挂在暂存里的重复 → 无条件跳过；你已经 `\不转` 掉、超时丢过、或已经转出去的 → 窗口内也不再翻出来。
  - `\转发状态` 里能看到「已记账 N 份」，日志里以 `↻ 暂存去重：…` 标出这一轮挡下了几份。
- **暂存编号每天从 1 重新开始**：按本地日期跨天归零，并自动跳过还挂着的编号（免得 `\转发 1` 指不清是哪条）；`\转发状态` 里会写「今天从 1 起」。
- **点名强发前的二次确认**：你 `\转发 <编号> <群号>` 点名的群如果**已经有**这条内容，插件第一次**只回报、不发**；10 分钟内同一个编号 + 同一批群**再回一次同样的口令**才真发过去 —— 免得手滑把重复内容又灌一遍群。
- **原文补推**：原文卡片首推失败、或被「一轮最多先发几张原文」截断的，插件会在下一轮自动补齐（同一条只补一次，不会让那个上限形同虚设）。

**改进**

- 目标群里**已经有**这条内容的群，**不再列进备选项**：询问的 `→`、`\转发状态` 的可转列表、auto 模式的候选列表都不列它，只补一句「X 里已经有这条了，没列进备选」，免得你选了才发现是重复的。
- 询问改成**逐条汇报**：每条都标 `📎 上面第 N 张卡片`，跟私聊里先发的那几张原始卡片一一对应，不用靠预览文字猜是哪条。
- `\转发 <编号> <群号>` 发不出去时，回报**具体原因**：`X 不在导向群列表里`（群号写错 / 没加进「目标群」）或 `X 现在不欠着这条了`（可能刚发过），不再是含糊的「可能已经有这条内容，或者群号写错了」。
- auto 模式下，模型点名要发已经发过的群时，插件会明确告诉它是**哪几个群**已经有、不用再发；给模型的提示词里也写清了这些群为什么不在候选里。
- 上架文案：插件简介改成大白话（不再堆术语），源码注释里的个人信息（QQ 号、群名、私人昵称）已清理，并随包附上这份说明书。

**移除**

- 旧的「多久没拍板就提醒一次」（原设置项，默认 20 分钟）连同那句「🔔 还有 N 条等你拍板」一起删掉 —— 现在 5 分钟就丢，提醒永远来不及。设置页也不再显示这一项。

### 1.0.0（2026-10-04）

首个版本：ask / auto 双模式（默认 ask，0 token）、按内容指纹判断每个目标群有没有发过、来源群兜底拉取、原文卡片先发一份、主人口令五条（`\转发` / `\不转` / `\转发状态` / `\转发测试` / `\转发帮助`）。
