# 宿傩讨伐战（sukuna-raid）v2.1.0

QQ 群里的**纯文字回合制** BOSS 战。多人**排队接力**挑战【两面宿傩】，每回合三选一出招。

> **v2.1.0 新增**：排队制 / 宿傩真身 / 旁白解说 / 魔虚罗 / 黑闪二选一转职 / 扩充卡组
> **v2.0.0 变更**：配图功能已全部移除（详见文末「为什么删掉了配图」）

---

## 一句话玩法

群友 @ 机器人 → 开局 → 战报末尾给三个选项 → 回「1」「2」「3」出招 → 如此往返。
多人同时上 → **排队**，前一个战死才轮到下一个。

宿傩**不是群成员**，他是机器人发出的**文字 BOSS**，不需要 @ 他。

| 三个选项 | 从卡池随机抽 3 个，**1. 2. 3.** 编号 |
| **旁白解说** | 电竞赛事风格的解说，负责画面感与情绪 |

## 排队制（v2.1.0）

多人同时参战 → **按顺序上场**，第一人打完轮到第二人。

**什么叫"打完"**：不是"打一回合就换人"，而是**战死**。
活着的人一直持有出场权，排队的人等他倒下才轮到。

> ⚠️ 为什么不做轮流制：宿傩每回合自愈 2%，如果每人只打一回合，
> 所有人的努力会被下一回合的自愈全部吃掉，战局**永远推进不了**。
> 所以"打完"必须是战死 —— 这也正好接上那句「下一个奔赴战场的是！」

实现上 `b.queue` 是权威数据源，`b.fighter` / `b.fighterName` 只是队首的**镜像**，
通过 `syncFighter()` 保持同步 —— 只有这一个地方写那两个字段，
否则会出现"队列说该 A 上，fighter 却写着 B"的鬼状态。

## 宿傩真身：四手平安宿傩（v2.1.0）

**同时面对 2 人以上**时，每回合 **30%** 概率变身。

| 项目 | 数值 |
|---|---|
| 触发门槛 | 场上 ≥ 2 人（含排队者） |
| 触发概率 | 每回合 30% |
| 变身收益 | **回血 20%**，且自愈速度 ×1.3 |
| 变身代价 | 技能威力降到 **30%~50%**（每回合现掷，制造波动） |
| 弱点 | **虎杖悠仁**的攻击伤害 **+50%** |
| 附赠 | 虎杖攻击时 **10%** 概率**眩晕**（宿傩停止行动一回合） |

> **设计意图**：真身不是纯加强，是**换形态** —— 变肉但变钝。
> 而且它把"人多"从数量优势变成**风险**：人越多他越可能变身。
> 这比"人多就赢"有意思。

眩晕触发时宿傩**整回合停摆**（既不自愈也不出手）—— 这正是"停止行动"该有的分量。

**为什么 +50% 和眩晕都挂在"虎杖"身上**：这是有意的。
它让虎杖这条转职路线有了**不可替代的战术价值**，
而不是单纯的数值更高（那伏黑就没人选了）。

## 黑闪 → 二选一转职（v2.1.0）

打出黑闪后**不自动进化**，而是弹出岔路，让本人自己选：

| | 虎杖悠仁 | 伏黑惠 |
|---|---|---|
| 实力 | 宿傩的 **30%** | 宿傩的 **25%** |
| 生命上限 | 150 | 130 |
| 卡组 | 基础 + 逕庭拳系 | 十种影法术（11 张） |
| 特色 | **真身的天敌**（+50% 伤害、10% 眩晕） | **唯一能召唤魔虚罗** |

> **为什么值得改成二选一**：原来黑闪只有一个结果，玩家没有决策 ——
> 黑闪是"运气"不是"选择"。现在它变成**岔路口**：
> 虎杖是高输出赌黑闪，伏黑是控场 + 底牌。
> 同一个运气事件有了两种打法。

### ⚠️ 输入约定：出招用数字，转职用名字

**转职必须回复名字**（「虎杖」/「伏黑」），**不能**用 1/2。

> 这里修过一个真实设计缺陷。最初转职也用 **1/2** 回复，结果和"出招选 1/2/3"
> **撞号**了：战报里出现的 `1.` `2.` 同时可能是转职路线也可能是出招选项，
> 光看数字分不出来。更糟的是那一回合**没法出招** ——
> 想打第 1 招却被当成选了虎杖。
>
> 症状很隐蔽：只有 12% 概率（黑闪触发率）才复现，
> 测试跑 6 次挂 1 次，看着像"随机失败"。
>
> 现在两套输入空间完全不重叠，而且战报里**两段都显示**，
> 玩家可以边打边想，不必卡着不回。

选转职**不消耗回合** —— 转职是奖励，不该因为"多花一回合选路"而白挨打。

## 魔虚罗（v2.1.0，本作最复杂的机制）

资料源：[百度百科「魔虚罗」](https://baike.baidu.com/item/%E9%AD%94%E8%99%9A%E7%BD%97/63622945)。
核心设定**照搬原著，不自行发明**。

### 怎么拿到

伏黑惠血量低于 **25%** 时，选项里**必定**出现【八握剑异戒神将魔虚罗】（带「(召)」标签）。

> ⚠️ 为什么不放进池子里随机抽：这是"血低于 25% 才能用"的**翻盘手段**，
> 玩家是拿命换来的机会。如果还要靠运气抽到，那这个机制在设计上就是失败的 ——
> 残血的人本来就快死了，他没时间等下一回合。
> 所以条件满足时**直接钉进选项第一位**，占掉一个位置。

### 出场序列

1. **吟唱一回合** —— 念出布瑠真言「布瑠部、由良由良、八握剑·异戒神将·魔虚罗」
2. 下一回合**登场，先咬召唤者 5%**（原著：召唤成功瞬间，召唤者即被它视为第一目标重创）
3. 召唤者**活下来** → 视角切换到魔虚罗，之后的选项变成它的招式
4. 召唤者**死了** → 魔虚罗失去锚点，消散

### 适应机制 —— 这是核心

魔虚罗有 **50 血**，背部法轮每回合转动。关键在于：

> **它适应的是「攻击类型」，不是具体某一招。**

| 同一类型挨打次数 | 效果 |
|---|---|
| 第 1 次 | 满伤，开始解析 |
| 第 2 次 | **减伤 50%** |
| 第 3 次起 | **完全免疫 —— 而且回满血** |

> ⚠️ "免疫时**回满血**"不是"减伤到 0"，性质完全不同：
> 玩家继续用被适应的招式打它，等于**在给敌人当奶妈**。
> 这条来自原著"极强恢复能力"，也是逼玩家换招的动力。

成功适应后才解锁【进化·术式篡夺】—— 把免疫掉的术式改造后据为己有，**攻击力翻倍**打回来。

招式池（全部取自原著）：
- **退魔之剑** —— 右臂的剑，剑身裹正极咒力（与反转术式同质），斩中即灭。**15% 概率被崩开**（这一剑落空）
- **神将之拳** —— 纯凭强悍肉身
- **适应反击** —— 把适应到的特性反过来利用，自带 50% 减伤
- **进化·术式篡夺** —— 攻击翻倍（需先完成适应）
- **再生** —— 强悍的肉身自我修复

### 宿傩的降伏序列

原文设定：对付魔虚罗的唯一办法是"用它没见过的招，在它适应之前秒杀"。
宿傩的应对是一条**状态机**：

```
active（打 3 回合）
  → realized（看穿："原来是适应……那就不给你适应的机会"）
  → locked（领域展开，把它钉到 1 血）
  → destroyed（下一回合「灶」清场）
```

**但每个阶段都留了破局窗口**：那一回合如果打出**眩晕或黑闪**，
领域的展开会被打断 / 「灶」无法成形，而且脚本会**回退一格**
（从 `realized` 重新开始）—— 所以"救下来"是有价值的，不是只延迟一回合。

## 血条：红蓝配色

```
两面宿傩·真身　🟥🟥🟥🟥🟥🟥🟥🟥🟥⬛ 87.0%　👹 四手平安宿傩
薛定谔　　　　🟦🟦🟦🟦🟦🟦🟦🟦🟦⬛ 85.0/100
```

**为什么是 emoji 而不是 ANSI 颜色码**：QQ 群消息是**纯文本**，
ANSI 转义序列不会渲染，只会变成一串看不见的怪字符。所以红蓝必须靠
**方块字符本身的语义色**：宿傩 🟥 / 我方 🟦 / 空槽 ⬛。

**为什么是 10 格不是 20 格**：emoji 宽度约为普通字符 2 倍，20 个会折行，
折行的血条读不出比例。10 格 + 百分比数字 = 清晰 > 精确。

## 核心规则

| 项目 | 设定 |
|---|---|
| 宿傩血量 | 100% |
| 宿傩自愈 | 每回合 2.0%；开反转术式后 3.5%；真身再 ×1.3 |
| 普通攻击 | 1.5%~2.2%（**刻意低于自愈**） |
| 黑闪 | **5% 伤害**，中断反转术式 **3 回合** |
| 咒术师实力 | 宿傩的 **20%** |
| 虎杖悠仁 | **30%** |
| 伏黑惠 | **25%** |

**为什么普通攻击打得过自愈就不行**：那样就变成"磨血"，十回合必赢，
黑闪从一个"赌一把的兴奋点"退化成"锦上添花"。现在普通攻击
**必然被自愈吃回去**，唯一能推进战局的是黑闪 —— 全局压力都压在
「这一拳能不能擦出黑闪」上。

## 数据存放

```
data/sukuna-raid/
├── battle/<chatKey>.json    会话级：宿傩血量/真身/眩晕/队列/魔虚罗/回合/阵亡名单/选项
├── players.json             玩家级（全局，按 userId）：血量、转职分支、黑闪次数
└── art/                     668 张，12 个角色 —— ⚠️ v2.0.0 后游戏已不再读取
```

**会话级 vs 玩家级（关键设计）**：宿傩/战局/队列是**会话级**；
玩家个人数据（转职、黑闪次数）是**全局按人**。

> ⚠️ 真实 `DATA_DIR` = `resources\app\data`。
> 但 `config.json` 在 `%LOCALAPPDATA%\Programs\QQ Agent\data`。
> **两个目录按文件类型分开**，写路径时别搞混（踩过：清理清错目录 → 旧战局残留）。

### ⚠️ players.json 是全局的，会跨群串数据

因为玩家数据按 `userId` 存全局，所以上个群打剩的 3 点血、
或者上个群里的 `alive:false`，都会原样带进**新群的第一局**。
症状是"一开局就被秒"，看着像数值崩了，其实是没清局内状态。

修法：**新局第一回合**和 **`reset`** 都会调 `reviveForNewGame()` ——
**转职保留**（跨局的个人进度），**血量与生死重置**（本局的东西）。

> 这个坑还牵出一个"承诺与实现不一致"的 bug：
> `canJoin()` 拒绝战死者时会说「**重开一局才能再上**」，
> 但 `reset` 只重建了 Battle，**从来没碰过 players.json** ——
> 玩家的 `alive:false` 一直留着，"重开"之后照样上不了场。

> ⚠️ 清理数据时**只删 `battle/` 和 `players.json`**，
> 千万别对整个目录 `rmSync recursive` —— 会连 `art/` 的 668 张素材一起清掉（踩过）。

## 工具

| 工具 | 用途 |
|---|---|
| `sukuna-raid__start` | 开局 |
| `sukuna-raid__choose` | **出招**（`choice` = "1"/"2"/"3" 或招式名）；转职回复时 `choice` 填「虎杖」/「伏黑」 |
| `sukuna-raid__join` | 上场/排队（被 @ 时用） |
| `sukuna-raid__status` | 看战况（含队列、真身、魔虚罗） |
| `sukuna-raid__reset` | 重开一局（会复活战死者并补满血） |

### 三个关键实现决定

**① 战报由技能自己发，不经模型转述。**
早期把战报当工具 `content` 返回，模型要么不复述、要么自己概括
「就这？连皮都没蹭掉」—— 群里什么都没了。**配图没了之后这条更重要**：
文字再丢就什么都不剩。

**② 工具 ctx 里没有 `triggerEntries`。**
只有 `before-context` / `before-tool` 钩子拿得到。用钩子按 `sessionId`
缓存本轮触发消息，工具里再取 —— 否则「@了却说你没@」的 bug 会复现。

**③ `handleDeath` 只剔除、不 shift。**
这里踩过一个很隐蔽的坑：先 `pruneDead` 再 `advanceQueue` 会**推进两次** ——
pruneDead 已经剔掉死者并同步了队首，再 shift 一次等于把
**下一个还活着的人**也踢出去。症状是"队列看着是对的，但第二个人永远上不了场"
（实测三人局：甲死后直接跳到丙，乙凭空消失）。
正确做法是只 `filter` 掉死者，然后 `syncFighter`。

### ⚠️ 写测试时注意两件事

**① 必须隔离 `QQ_AGENT_DATA_DIR`。**
`test_image_send.mjs` 原来没隔离，战局写进了真实数据目录，
而玩家血量/生死是**跨进程保留**的 —— 上一次跑剩的残血会被带进来，
开局第一回合就被秒。表现出来是"跑 10 次挂 6 次"的幽灵 bug。
