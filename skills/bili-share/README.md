# 分享B站视频（bili-share）

让机器人**主动分享** B 站视频：

- 给链接 → 转发该视频
- 给关键词 → 搜一条最合适的发出来

都是**下载视频本体** + 附标题 / UP 主 / 时长 / 原链接。

## 依赖

系统里要有 **ffmpeg**（B 站视频通常是音视频分离的，需要合并）。

## 搜索是怎么挑的

不是简单按播放量取第一条 —— 实测有坑：

- 搜索词「伊莫可Imoko」返回的 20 条作者全是本人，但**一旦加词**变成「伊莫可Imoko 鼠小妹」，
  前 5 条就只剩 2 条是本人、其余是别人的二创剪辑。所以默认用 **`up-first`**：用名字比对把本人的提到前面。
- 高播放里混着大量**循环歌单 / 助眠合集**（实测有 60:18、32:00 的），它们会稳定赢下播放量排序，
  但不适合当「给别人听一首歌」。所以有**时长上下限**。
- 第一次搜索**一条本人都没有**时，用 B 站搜索建议把词补完整再搜一次
  （实测搜「伊莫可」建议会给出完整名字「伊莫可Imoko」，补全后能搜到更多本人投稿；
  而搜「伊莫」时建议给的是它自己，就不会乱改词）。**只在完全没搜到本人时触发**，不会把你原本能用的词换掉。

## 设置

| 项 | 默认 | 说明 |
|---|---|---|
| 清晰度（qn） | 16 | 16=360P、32=480P、64=720P。无 Cookie 时只保证 360P/480P |
| 体积上限（MB） | 100 | 超过就只发链接不下载 |
| 下载超时（毫秒） | 60000 | |
| 视频落地目录 | 空 | 留空 = 应用 `data/bili-media`，超 2 小时自动清理 |
| 搜索结果排序 | up-first | 见上文 |
| 时长上限（秒） | 1800 | 填 0 = 不限制 |
| 时长下限（秒） | 0 | 想避开十几秒碎片可设 30 左右 |
| UP 模式排序 | click | `click`=按播放量（直接看这个 UP 最火的）；`pubdate`=按最新发布。UP 模式按 uid 精确取，不会混进别人的二创。同一 UP 的投稿列表缓存 6 小时（B 站该接口调太勤会被限流） |
| 关键词模糊补救 | 开 | 见上文 |
